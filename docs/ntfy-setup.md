# ntfy mobile push setup

Configure the service as a care-circle owner, then have each receiving caregiver
save their preferences for the selected care recipient. All sends require review
and approval. **Credentials configured** does not verify provider access.

Use [local configuration](notification-setup.md#local-configuration),
[cloud configuration](notification-setup.md#production), or encrypted overrides
under **Manage settings → Environment configuration** (see
[override setup and recovery](deployment.md#encrypted-integration-overrides)).
After configuring, switch the integration on separately.

## Where to find the configuration values

| Variable / preference | Where to find or create it | What to use |
| --- | --- | --- |
| `NTFY_SERVER_URL` | Choose the hosted service or ask the operator of your self-hosted ntfy server for its public HTTPS origin. | `https://ntfy.sh` for the public service, or `https://YOUR-NTFY-HOST` for your server. Do not append a topic or an account page path. |
| `NTFY_ACCESS_TOKEN` (optional) | Sign in to the selected server's ntfy web app and open account settings to create an access token, where supported. On a self-hosted server, an administrator can generate a user token with `ntfy token add USERNAME`. | A token for a user allowed to publish to the chosen topic on that same server. Leave unset if publishing needs no authentication. |
| Mobile push topic (caregiver preference) | Choose a topic and subscribe to it in the phone app on the selected server. For protected topics, arrange access with the server operator/account first. | Enter the same topic name in Carestead's Mobile push preferences. It is not an environment variable and is not generated by Carestead. |

See [ntfy access tokens](https://docs.ntfy.sh/config/#access-tokens) and
[phone subscriptions](https://docs.ntfy.sh/subscribe/phone/).
The publisher token does not grant the phone subscription access automatically;
configure the phone's authentication separately when needed.

## Setup and receipt check

1. Install the ntfy app on your phone.
2. Set `NTFY_SERVER_URL=https://ntfy.sh` in `web/.dev.vars`, or use your own
   HTTPS ntfy server origin (no topic path). Optionally set `NTFY_ACCESS_TOKEN`
   to a publisher access token. For cloud, use `web/.secrets.cloudflare` and the
   existing secrets check/apply commands.
3. Rebuild local Docker with `make up`. For cloud, run `make cloud-release` to
   apply the ntfy preferences migration and deploy, then apply your secrets.
4. An owner enables **Account settings → Integrations → Mobile push**.
5. In the phone app, subscribe to a topic on the same server. In Carestead,
   open **Account settings → Integrations → Mobile push → Manage settings**, enter that topic, and select **Enable mobile push**.
6. Ask `ntfy me: There is a care update to review.` Review and approve the
   message, then verify receipt on the phone.

Use an access-controlled topic for care details. Public topics are readable by
anyone who knows their name; a publisher token alone does not make a topic private.
Every subscriber with access receives the message. Topic ownership is not verified
when saving. Configure subscription credentials in the phone app when needed.
For self-hosted iPhone delivery, follow ntfy's upstream server setup instructions.

This channel uses ntfy for mobile push. It requires no browser subscription or
VAPID keys. It is on-demand, with approval for each message and no automatic
retries. `accepted` means the server accepted the message, not confirmed phone
receipt. Topic names and access tokens are excluded from previews, delivery
history and exports. Disabling removes the saved topic; changing the topic blocks
old approvals. Changing the server requires saving a topic again. Recipient
deletion removes ntfy preferences. Already sent messages cannot be recalled.

References: [ntfy publishing API](https://docs.ntfy.sh/publish/),
[phone subscriptions](https://docs.ntfy.sh/subscribe/phone/),
[self-hosted iOS push](https://docs.ntfy.sh/config/#ios-instant-notifications).

Delivery preferences are managed in **Account settings → Integrations**, under the corresponding email, SMS, mobile push, or browser push option. Preferences apply to the signed-in caregiver and selected care recipient. The Notifications page has a separate **Recent delivery attempts** container with a link to Integrations.

## Troubleshooting

| Symptom | Check and recovery |
| --- | --- |
| Server configuration rejected | Use an HTTPS origin such as `https://ntfy.sh`, with no topic path, query, fragment, or embedded username/password. Put publisher credentials in `NTFY_ACCESS_TOKEN`. |
| Topic cannot be saved | Enter only the topic name: 1–64 letters, digits, underscores or hyphens. Reserved names `app`, `docs`, `static`, `file`, `v1`, `health`, and `metrics` are rejected. |
| `channel_disabled` after changing server | Subscribe on the new server in the phone app and save the topic again in Carestead for each recipient. Older error text may mention Notifications; preferences now live in Integrations. |
| `provider_http_401` / `provider_http_403` | Check the publisher token belongs to this server and can publish to the topic. The phone also needs subscription access when the topic is protected. |
| `accepted` but no phone alert | Check the exact server and case-sensitive topic on the phone, subscription credentials, and device notification permission. Every authorized subscriber to that topic receives the message. |
| Self-hosted iPhone alerts are delayed | Check the ntfy server's [iOS upstream configuration](https://docs.ntfy.sh/config/#ios-instant-notifications). Carestead's server URL/token alone does not configure that upstream. |
| `missing_provider_receipt` | Carestead did not receive a matching ntfy message receipt. Inspect server history/logs before preparing another send. |

See [shared troubleshooting](notification-setup.md#shared-troubleshooting) for
consent, changed destinations, and uncertain sends. Never repeat an ambiguous
send before checking provider history and the receiving device.
