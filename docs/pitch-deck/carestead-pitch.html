Profile, communication and mobility needs, support contacts, and a versioned care plan.

+CaresteadASK · REVIEW · APPROVE

From “What needs attention?”
to a reviewed action.

Ask in the moment

Recipient-specific text chat returns a summary with expandable supporting evidence.

Prepare a concrete change

Reschedule an appointment, assign a ride, add a responsibility, run a check, or draft an in-app update.

Approve, then record the result

An authorized caregiver reviews the action. The app executes it and saves the outcome and audit trail.

Voice option: browser dictation and spoken replies, where supported. Raw audio is not retained by Carestead.

Current actions update Carestead · external calendar/email/SMS unconnected
Actual chat workflow · typed proposals and deterministic intent matching

Updating an appointment record does not book an external calendar or verify real-world attendance.
+CaresteadHOW IT WORKS

Structured state grounds the agent.
Human approval controls the write.

1 · Observe

Caregiver input

Task updates, chat requests, or a care check.

2 · Retrieve

Authorized context

Profile, tasks, events, trusted facts, risks, and contacts.

3 · Decide

Rules + typed tools

Return a grounded answer or propose a supported action.

4 · Review

Policy + approval

Recheck role and consent. Execute approved writes only.

5 · Record

State + trace

Save the change, evidence, tool outcome, and audit entry.

React / Vinext → API → Cloudflare D1

One care-state agent. Structured retrieval supplies grounded context; deterministic rules and intent matching drive decisions.

No separate vector database, Mem0 service, or LLM in the current decision path.

Explicit decision branches

Question → answer with evidence
Missing context → request clarification / no match
Proposed action → approve or cancel
Denied permission or consent → block

Code: lib/risk-engine.ts · lib/auth.ts · lib/guardrails.ts · app/api/chat/route.ts05 / 07
This describes the current implementation, not all capabilities proposed in the local project overview. Care checks currently detect an open medication task or an unassigned task. The chat also uses a simple appointment-proximity conflict check. Scheduled monitoring, pharmacy connectors, richer dependency calculations and an LLM adapter remain future work. API responses and state loading drive refreshes; a background event-stream monitor was not established. Current local auth uses password hashes and sessions, superseding the older document's private-Site identity description.

+CaresteadKEEP THE CAREGIVER IN CONTROL

Useful support, with a clear
boundary around autonomy.

Permission before action

Server-enforced recipient roles, explicit approval for chat writes, and approval-aware in-app notifications.

Control over personal data

Consent withdrawal, retention choices, owner export and confirmed deletion; validation, rate limits, and privacy-safe error metadata.

Coordination only

No diagnosis, prescribing, or replacement for clinical judgment or emergency services.

Verified in the local walkthrough

Grounded chat; no task change before approval; task updated after approval. Automated WCAG checks on four surfaces.

Next: prove caregiver value

Close the four benchmark gaps. Add expert-reviewed cases. Measure verified task completion, caregiver effort, and unnecessary alerts.

Guardrails reduce risk; they do not establish clinical readiness. Real-world completion and emergency handling need further validation.

Know what matters. Share the responsibility. Approve the next step.
